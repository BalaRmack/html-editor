# Интеграции и экспорт

Базовая поставка намеренно содержит только локальные сценарии:

- копирование в буфер обмена;
- вставка в активное поле;
- локальная история.

Удалённые сервисы (Notion, Gmail, Google Docs и т.п.) **не реализованы и не подключены**. Архитектура оставляет для них место, чтобы не тянуть OAuth/HTTP-зависимости в локальное ядро.

## Контракт

```csharp
public interface IExportProvider
{
    string Id { get; }
    string DisplayName { get; }
    bool SendsOverNetwork { get; }
    bool IsConfigured { get; }
    Task ConnectAsync(CancellationToken ct = default);
    Task ExportAsync(string text, CancellationToken ct = default);
    Task DisconnectAsync(CancellationToken ct = default);
}
```

Провайдеры регистрируются в `ExportProviderRegistry`. По умолчанию реестр пуст. UI показывает удалённый экспорт только для `SendsOverNetwork && IsConfigured`.

## Правила для будущего провайдера

1. **Явное подключение.** `ConnectAsync` вызывается только по кнопке пользователя и выполняется вне UI-потока.
2. **OAuth.** Использовать системный браузер / loopback redirect, PKCE, state. Не встраивать WebView с паролем. Токены хранить в Windows Credential Manager / DPAPI.
3. **Явная отправка.** `ExportAsync` вызывается только после прямого действия пользователя с текущим текстом. Никакой автоотправки истории или аудио.
4. **Минимальные scope.** Запрашивать только необходимые права.
5. **Отключение.** `DisconnectAsync` удаляет локальные токены и скрывает провайдера из активного экспорта.
6. **Ошибки.** Понятные сообщения об истёкшем токене, отсутствии сети и запрете доступа; без логирования текста.

## Почему не всё сразу

Local-first диктовка не должна зависеть от облачных аккаунтов. Провайдеры добавляются отдельными проверяемыми модулями после того, как базовый сценарий стабилен.
